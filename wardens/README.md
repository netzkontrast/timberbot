# The Wardens (faction mod, v0.2)

Design: [`../design/faction-wardens.md`](../design/faction-wardens.md), Chapter 1 plan:
[`../design/wardens-chapter-1-plan.md`](../design/wardens-chapter-1-plan.md).
Playtesting with an agent: [`playtest/PLAYTEST.md`](playtest/PLAYTEST.md).

The mod is three things in one DLL:

1. **The faction** (JSON blueprints): bots as starting population, four Data needs, Data Core
   and Firmware goods, and the Wardens tutorial: the Folktails tutorial ported to bots, tutorial
   for tutorial (18 of them, `tools/gen_tutorial.py`).
2. **The Timberbot API**, compiled in from `src/Timberbot/` (namespace `Timberbot`): HTTP on
   8085, WebSocket on 8086, the in-game widget, autoload. Same code as the standalone mod;
   the standalone **Timberbot API mod must be disabled** when this one is enabled.
3. **An in-game MCP server** (`src/Wardens*.cs`): Model Context Protocol over HTTP on
   127.0.0.1:8090 so Claude Code connects straight into the running game (`.mcp.json` in
   the repo root). Tools: chat with the player, point at tiles, camera flights, tutorial
   state, and a passthrough to the whole Timberbot API.

```

  Factions/*.WardensModifier…        recipe appends; VanillaTutorial… keeps the 18 vanilla tutorials off

  Collections/ Needs/ Goods/ Recipes/ Localizations/

  WardensPoweredStep.cs              PoweredBuildingStepSpec: "Power: X" with our own shaft buttons
  WardensPopulationStep.cs           BeaversStepSpec: "Beavers: (n/m)" for the first pod-born beaver
  WardensTriggers.cs                 MissingDam / PlatformBuilt / IdleWardens triggers (optional tutorials)
  WardensColdBoot.cs                 start-of-run cutscene: paused orbit around the Core
  WardensCameraDirector.cs           keyframe camera flights (cutscene, MCP, trailer)
  WardensPointer.cs                  highlight + arrow + toast on a tile ("look here")
```

Build: `dotnet build wardens/src/Wardens.csproj -c Release`; every build bumps the patch version
(`tools/bump_version.py`, run by the BumpVersion target) in manifest.json, the MCP server constant
and the csproj, so the mod manager shows which build is deployed. (Uses the git-ignored
`src/Directory.Build.props` for the game path; pass `-p:GameManagedDir=… -p:ModDir=…` otherwise).

## How the tutorial works

- Vanilla only runs tutorials for a faction carrying `StartingFactionSpec` (Folktails); the
  Wardens carry it too, which also puts the tutorial toggle on the new-game panel.
- Vanilla's 18 tutorials are Folktails-specific (they reference `Inventor.Folktails` etc.), so a
  faction blueprint modifier gives each of them `RequiredTutorialIds: ["Wardens.NeverFinished"]`
  and no stages (their steps are deserialized at load for every faction, and would throw).
- The Wardens line mirrors the vanilla chain stage for stage, with the Wardens' buildings and voice
  (table in `tools/gen_tutorial.py`): Cold Boot → Basics → Scrap → Badwater and Biomass → Working
  hours → Storage / Science → Pods → Power and pods → First beaver → Reforestation → Maintenance,
  plus the event-driven ones (Dams, Vertical architecture, Droughts, Badtides, Haulers, Layer tool).
- Vanilla's trigger singletons are Folktails-only too. `WardensTriggers.cs` re-implements the dam,
  platform and idle-workforce triggers with Wardens names and bots; the weather triggers are
  faction-neutral and reused; `StairsUnlockedTrigger` resolves `Stairs.Folktails` at load no matter
  what, so `Stairs.Wardens` carries that name as a `BackwardCompatibleTemplateNames` alias.
- Step types of our own: `GoodStockStepSpec`, `BotsChargedStepSpec`, `PoweredBuildingStepSpec`
  (vanilla's "Power:" step highlights hardcoded Folktails shafts), `BeaversStepSpec`.
- `tools/validate.py` resolves every name the game looks up at load (collection blueprints, tutorial
  templates/goods/plantables, loc keys, planter groups) against the deployed mod + vanilla; run it
  after every generator change.
- Finishing a tutorial posts `TutorialFinishedEvent`, the hook for the chapter unlock service.

Act I only. Out of scope for now: breeding pods, remediation, the Ark, custom art, the wasteland map.

## Art (v0.2)

`Sprites/` and `Materials/` hold the faction's 2D art: avatars, logo, new-game portrait, five
beaver skins, the bot skin, banners, carrying-model and zipline textures. They are derived from
Bobingabout's Leaf Coats mod by `tools/recolor_assets.py` (greens to cyan-blue, browns to slate,
cool glow on highlights); `tools/recolor-sheet.png` shows before/after. Private derivation, see
`Sprites/ATTRIBUTION.md`. Avatars and beaver skins are wired through `FactionSpec`; the bot skin,
carrying models and zipline cable are applied at runtime by `WardensMaterialPatcher` (vanilla has
no JSON hook for those materials; Leaf Coats uses the BobingaboutScriptPack for the same job).
Building models are still Iron Teeth; the Leaf Coats asset bundle could not be opened with UnityPy
(newer Unity serialization), so 3D assets are a Blender/Unity job, not a copy.

`WardensFullNewGame.png` is the big portrait on the New Game faction-select screen
(`FactionSpec.NewGameFullAvatar`, drawn by `Timberborn.MainMenuPanels.NewGameFactionPanel` with
`-unity-background-scale-mode: scale-to-fit` into a 210x280/156x210 box — any aspect letterboxes
safely, but the mod's convention is a 420x560 (3:4) transparent-background cutout). AI-generated
character art (image-gen prompt in `design/wardens-art-path.md`) gets fitted to that canvas with
`tools/install_avatar.py <source.png>`: pads to 3:4 without cropping the character, then resizes
with alpha premultiplied so fully-transparent-but-black source pixels don't fringe the edges.

## Buildings (v0.2, generated)

`tools/gen_buildings.py` re-specs Iron Teeth blueprints from the game's own `Blueprints.zip` into
`Buildings/`, `NaturalResources/`, `Goods/Good.Biomass` and the two Wardens template collections.
Models stay vanilla references. Everything costs Scrap Metal (the Scavenger Flag is the only source);
science cost is 0 until the chapter unlock service exists.

| Template | From | What changed |
|---|---|---|
| `Core.Wardens` (starting building) | DistrictCenter.IronTeeth | + 150 hp power output |
| `ChargingPost.Wardens` | ChargingStation.IronTeeth | Scrap 5, no science; 50 hp input |
| `Cruncher.Wardens` | Numbercruncher.IronTeeth | 120 hp input; recipes Science Points or Data Core; Scrap 20 |
| `SludgeBurner.Wardens` | SteamEngine.IronTeeth | burns Biomass (no water), 200 hp, `PollutingBuildingSpec` |
| `PowerShaft.Wardens`, `ScrapPile.Wardens` | PowerShaft / SmallIndustrialPile | scrap prices |
| `ReedBed.Wardens` | FarmHouse.IronTeeth | plants Sludge Reed |
| `BreedingPod.Wardens` | BreedingPod.IronTeeth | nutrients Biomass; 100 hp power input (transputs on every tile) |
| `AdvancedBreedingPod.Wardens` | AdvancedBreedingPod.IronTeeth | Biomass + Firmware; 150 hp; costs Scrap 20 + Data Core 5 |
| `SludgePump.Wardens` | DeepBadwaterPump.IronTeeth | the unlocked pump: badwater from day one, Scrap 12, bots work it free |
| `BadwaterCell.Wardens` | SteamEngine.IronTeeth | early generator: burns Badwater 0.4/h for 100 hp, Scrap 8, cyan light, small pollution |
| `SludgeTank.Wardens` | SmallTank.IronTeeth | Scrap 6 |
| `Planter.Wardens` | Forester.IronTeeth | exists because the bar must hold exactly one tree-planter building (bottom-bar rule) |
| `SludgeReed` (crop) | Cattail models on a Kohlrabi body | Farmhouse group, 4 days, yields Biomass 3, no contamination/drought death |

Art direction from here: [`../design/wardens-art-path.md`](../design/wardens-art-path.md).
The faction's building bar is `TemplateCollection.Buildings.Wardens` (the twelve above plus the vanilla
Scavenger Flag), no longer the whole Iron Teeth set. Recipes: Data Core = Scrap Metal 1 + Badwater 5,
Firmware = Data Core 2 + Scrap Metal 1.

## Leaf Coats port (local only)

`tools/import_leafcoats.py` copies the Leaf Coats family (base + Badwater + Explosives + Beaver Plants)
and the code it needs (Bobingabout Script Pack, Vertical Nav Mesh) into `src/` for local deployment:
241 files, 168 MB, all listed in `src/.leafcoats-import.txt` and git-ignored through `src/.gitignore`.
`--remove` takes them out again. With the copies in the mod, **disable the seven workshop mods** (Leaf Coats + 3 add-ons, Script Pack, Vertical Nav Mesh, Harmony: Vertical Nav Mesh is a Harmony patch).
The analysis and the file-by-file port plan are in
[`../design/leafcoats-port-plan.md`](../design/leafcoats-port-plan.md); the building blueprints
inside their bundle are read with the MCP tool `dump_assets` (writes to `Mods/Wardens/dump/`).
